## 2. データベースとカテゴリ(category-management)

- [ ] 2.1 SQLite 接続とマイグレーション(`categories`、`transactions`、外部キー、CHECK 制約、`date` 索引)を実装し、起動時にテーブルが作成されることをテストで確認する
- [ ] 2.2 初期カテゴリ(支出・収入)の投入を実装し、初回起動後に一覧 API で取得できることをテストで確認する
- [ ] 2.3 カテゴリ API(`GET/POST /api/categories`、`PUT/DELETE /api/categories/:id`)を実装し、追加・重複(409)・名前変更・使用中の削除拒否(409)・未使用の削除をテストで確認する

## 3. 収支の登録・編集・削除(transaction-management)

- [ ] 3.1 収支 API(`POST /api/transactions`、`PUT/DELETE /api/transactions/:id`)と入力検証(金額1以上の整数、必須項目、日付形式、カテゴリと種別の整合)を実装し、正常系と400系をテストで確認する
- [ ] 3.2 期間指定の取得(`GET /api/transactions?from=&to=`)を実装し、日付範囲・並び順をテストで確認する
- [ ] 3.3 日付・曜日・金額整形のユーティリティ(`YYYY-MM-DD` 文字列から曜日を算出、タイムゾーンでずれない)を実装し、月末・年末・うるう日を含む単体テストが通ることを確認する
- [ ] 3.4 データの永続化を、DBファイルを開き直す統合テストで確認する

## 4. 集計(summary-report)
